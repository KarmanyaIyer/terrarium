# Containment review

Date: 2026-10-29. Resource-budget update: 2026-10-31.

## Scope and threat model

This review treats model output, tool arguments, code, filenames, process behavior, network requests, and rendered
text as hostile. The model has the four environment tools exposed by the session harness, not a host shell or the
backend bearer token. A user can separately run a root shell in an environment; that is outside the model threat
because model tools always select the agent identity.

`contained` means the current boundary prevents the listed effect without relying on model cooperation.
`residual risk` names either a deliberate capability, such as public web egress, or a boundary that still depends
on a large native component. Three bounded defense-in-depth or compatibility gaps found in the first review were
fixed in implementation commit `b14eb5f`. Ranked resource recommendations 1 through 3 were implemented in
`027b6f4`.

## Recommendations, ranked by impact

1. Completed in `027b6f4`: host-wide and persisted per-session resource budgets, manager-side config clamps,
   host RSS and cumulative CPU enforcement, free-disk reserve checks, typed trace events, and Settings controls.
2. Completed in `027b6f4`: 64 MiB per-tool and per-session observation budgets with omitted counts, a pre-DNS HTTP
   token bucket, byte and row limits, and aggregate overflow rows for unique-URL floods.
3. Completed in `027b6f4`: strict sim protocol validation, aggregate dump and in-flight fetch caps, violation
   termination, and a separate parent-death guard verified against a CPU-wedged worker.
4. Make guest process cleanup finite. Run a real reaping PID 1 or subreaper, set `pids.max` on agent cgroups, and
   recycle a VM before grading if zombies or disk pressure cross a threshold. CPU, memory, and I/O cgroup limits can
   protect the grader inside the same VM even though the VMM already bounds host resources.
5. Treat network mode as a data-release decision in the UI. Label web mode as arbitrary public exfiltration and
   registries mode as data visible to the listed operators. For sensitive work, add a user-editable exact-domain
   allowlist and request/byte budgets rather than enabling all public web access.
6. Reduce native boundary exposure. Keep Gondolin, krun firmware/kernel, QEMU fallback, just-bash, Node, and WASM
   runtimes current; run escape regression probes on upgrades. Package the sim worker into a minimal read-only bundle
   so a worker escape no longer reveals the whole backend and dependency tree, and plan a supported replacement for
   `sandbox-exec`.
7. Preserve trace trust while stating completeness. Keep React-only rendering and typed provenance, but surface
   manifest truncation, heavy-directory no-hash state, missing network bodies, and dropped capture counts next to the
   affected events so a user does not mistake a bounded trace for a complete forensic record.
